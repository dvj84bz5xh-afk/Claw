### 学习项目: yvgude/lean-ctx (LeanCTX)
- URL: https://github.com/yvgude/lean-ctx
- Stars: 3,894 | 语言: Rust | 最近更新: 2026-10-19 | License: Apache-2.0 (Mixed)
- 一句话: **Context Gateway** — 插在 AI 工具与它要读的信息之间，按任务选择上下文、按策略控制交付、记录可验证证据；应用/Agent loop/模型仍归你

### 项目概述
不做 Agent 框架，只做**上下文网关**：文件、仓库、工具结果、外部 provider 的输出先经过 LeanCTX，再由它决定"给模型看什么、以什么粒度看、看到多少 token、留下什么证据"。四段式职责 **Select · Control · Learn · Prove**，以 CLI / MCP / hooks / proxy 四种入口接入 Claude Code、Cursor、Codex 等现有工具，模型调用仍由宿主完成。

### 核心发现
1. **16 种读取模式 + 缓存引用**：`full` / `map` / `signatures` / `diff` / `lines:N-M` / `density:X` …；**重复读取已缓存文件时返回紧凑引用而非重发全文**——这是"上下文缓存复用"的正确形态（引用可换回原文）。
2. **JIT 披露（按需展开）**：`signatures` 输出带行号区间，只给签名+span，正文用 `lines:N-M` 定向展开；先骨架后血肉，把"读多少"变成逐步决策而不是一次赌注。
3. **`density:0.4` 确定性预算压缩**：保留最高熵行直到只剩约 40% token，**确定性可复现**（不是 LLM 摘要），因此可缓存、可 diff、可回归测试。
4. **Shell 输出模式压缩**：85+ 种命令输出模式（git/npm/cargo/docker/kubectl/terraform）+ 250+ 直通规则——工具输出不该原样进上下文。
5. **Tree-sitter AST 结构理解（27 语言）**：按结构压缩与检索，而非纯文本截断。
6. **Control 交付前控制面**：PathJail + 角色限制文件访问范围；内容过滤支持 warn / redact / block 三档；context budget 限制选中输入与工具输出；明确承认"文件系统边界不是操作系统沙箱"。
7. **Learn = 上下文连续性，不是训练模型**：Session memory(CCP) 持久化 task/facts/decisions 且**压缩后仍可结构化恢复**；知识图为带有效期窗的时间事实（episodic + procedural）；Property Graph 多边代码图（imports/calls/exports/type_ref）用于影响分析与检索排序。
8. **Prove 证据链**：`ctx_proof`/`ctx_verify` 导出审计轨迹（verifier / SLO / pipeline / provenance）+ 运行时校验策略声明（每个被触文件的 PathJail、预算）；并诚实声明"仅上下文集成只能证明自己准备了什么，无法证明宿主后续的模型调用"。
9. **反虚高指标的方法论（最有价值的一点）**：主动**撤回**过去宣传的压缩率表格（因未声明工作负载与方法），改为"自己仓库自己测"；把 **估算 / provider 实测 / 结果质量** 三者严格分离；Shadow Mode 明确标注为**模拟基线**（未用 provider prompt cache，只估成本不证质量）；提供 CPAO（cost per accepted outcome）作为比较口径；非 LLM 的 A/B 门禁 + off-vs-on testbench（同一 token 预算、LLM judge + 仓库自带测试）才允许谈效果。

### 改进建议
1. **[P0][context_injector] 分级读取模式 + JIT 披露 + 缓存引用**：为文件读取定义模式枚举（full / map / signatures / diff / lines:N-M / density:X），默认先给 signatures+span，需要时再按区间展开；对内容未变的重复读取返回内容指纹引用（content hash → ref）而非重发全文，并提供 `expand(ref)` 换回原文。价值: 直接砍掉重复读取与全文件注入，且每一步"读多少"可审计。
2. **[P0][tool_registry] 工具输出压缩规则库 + 输出预算**：按命令族（git/npm/pytest/pip/docker）维护"高价值行提取 + 噪音剔除"规则与直通白名单，工具结果统一过"输出预算"（如单次 ≤N tok，超出转 ref 可展开）。价值: 工具结果通常是上下文膨胀主因，规则化压缩比通用摘要更可控、可测试。
3. **[P1][eval_observability] 证据分级报告法（估算/实测/质量三分 + CPAO）**：所有指标标注来源等级——估算（模拟基线）/ 供应商实测 / 结果质量评测，禁止混用；无声明工作负载与方法的数字不得对外展示（历史数字主动标注撤回）；新增 CPAO（cost per accepted outcome）作为主口径。价值: 让"改进是否真实有效"可被第三方复核，避免自我宣传式虚高。
4. **[P1][memory_system] CCP 结构化会话记忆 + 时间有效窗**：把 task/facts/decisions 存为结构化记录（而非段落摘要），提供 `recover(task_id)` 结构化查询，确保压缩后仍能精确取回约束与决策；事实类记忆带 valid_from/valid_to，检索默认只返回当前有效版本。价值: 解决"压缩后知道有这事但取不出细节"与"过期事实污染决策"。
5. **[P2][claw_integration] 交付前控制面（PathJail + 内容过滤三档 + 上下文预算）**：在"交给模型之前"统一执行路径白名单、敏感内容 warn/redact/block、单次上下文预算；并对每次拦截记录策略判定与被触文件，形成可导出证据。价值: 把安全与成本控制集中到一个可测的关口，而非散落在各工具实现里。

### 对 Claw 的定位判断
LeanCTX 与 Claw 不是竞争关系而是**缺口的镜像**：Claw 强在"记忆/技能的表达与编排"，LeanCTX 强在"上下文进入模型前的那道关口"——选择、裁剪、控制、举证。Claw 当前 `context_injector` 只是"注入器"，没有"网关"语义（无模式化读取、无缓存引用、无输出预算、无交付前策略判定）。建议把 P0 两项做成 `context_injector` 的"读取-压缩-举证"三层，与已有技能三级 token 控制、五层分层加载拼成完整链路；P1 证据分级法可直接约束进化引擎自身的指标口径（避免"压缩率"这类无法复核的宣传数字）。
