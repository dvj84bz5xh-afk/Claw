- 定位: AI 原生代理服务器与数据平面（基于 Envoy）— 智能LLM路由、Agent编排、可观测性、Guardrails，把"生产化管道"从应用代码中剥离

### 项目概述
构建 Agent Demo 容易，把 Agent 应用安全可靠地送进生产却很难：路由逻辑、护栏钩子、评估与可观测性胶水代码、各框架的模型适配 quirk——这些"隐藏中间件"每套代码库都要重写。Plano 将这些核心交付关注点统一收敛到一个**进程外数据平面（out-of-process dataplane）**，应用代码只保留核心业务逻辑。

### 核心发现
1. **进程外数据平面架构** — 路由/护栏/追踪/模型适配全部下沉到独立代理层（Envoy 内核），Agent 应用不感知；新增 Agent 无需改应用代码，只改 YAML 配置重启即可
2. **YAML 声明式 Agent 编排** — 在 config.yaml 中声明 Agent URL + 自然语言描述，意图分类器和路由逻辑自动生成；"What you declare vs what you don't write" 清单极具工程价值
3. **轻量专用路由模型** — 用自研 4B 参数编排模型（Plano-Orchestrator）做意图路由，替代 GPT-4 级大模型，生产级路由的成本和延迟降低一个数量级
4. **Model Agility 统一路由 API** — 按模型名/别名（语义名）/自动偏好路由，统一 LLM API 吸收各 provider 的 quirk 与状态管理
5. **零代码 Agentic Signals + OTEL** — 代理层自动捕获端到端追踪与 Agentic 信号（含 `random_sampling` 采样率配置），应用零埋点，评估数据即拿即用
6. **Filter Chain 护栏体系** — 越狱防护/内容审核/记忆钩子以模块化过滤器链形式挂在代理层，全 Agent 统一生效

### 改进建议
1. **P0 model_scheduler**: Agent 声明式路由 — YAML 声明 Agent 端点+自然语言描述，自动生成意图分类路由（区别于已pending的CCR规则路由：plano是语义意图驱动，非规则匹配）
2. **P0 agent_orchestrator**: 编排数据面解耦 — Orchestrator 独立为进程外服务，业务 Agent 注册即接入，扩容不改代码
3. **P1 model_scheduler**: 轻量意图路由模型 — 本地小模型（≤4B）做任务→Agent映射，替代每次调用大模型判定，降低成本与延迟
4. **P1 eval_observability**: 零代码信号采集 — 在调度层自动捕获每次 Agent 调用的追踪与信号，支持采样率配置，供评估管道消费
5. **P2 agent_orchestrator**: Filter Chain 护栏链 — 入口处模块化过滤器（安全审核/敏感词/记忆注入），全 Agent 统一挂载
