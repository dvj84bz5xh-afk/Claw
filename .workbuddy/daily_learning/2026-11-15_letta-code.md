- URL: https://github.com/letta-ai/letta-code

- 定位: 有状态的 agent harness —— “agents that are more like people than tools”，通过重写自己的记忆、技能、提示乃至 harness 来长期进化
- 出身: MemGPT 与 sleep-time compute（dreaming）作者团队

### 核心发现

1. **记忆就是一个 git 仓库，每次编辑都是一次 commit**
   MemFS = 投影到本机的一棵真实 checkout，agent 用普通文件工具读写；提交并推送后，才成为“它在任何机器上的记忆”。
   这一条同时解决三件事：**版本历史**（能 diff 能回滚）、**冲突处理**（用 git 而不是覆盖）、**边界**（“已保存的记忆”与“未提交的改动”分开）。

2. **路径即策略：选位置就是选“是否常驻上下文”**
   根目录文件每轮进系统提示；带自己 `MEMORY.md` 索引的子目录**不进上下文**，直到需要时才被读。
   根 `MEMORY.md` 只列子目录，于是**目录名与文件名本身就是路标**——active context 保持精简，深层资料仍可查。

3. ** dreaming：整理发生在关键路径之外，且有明确触发条件**
   后台 subagent 复盘近期会话、合并可复用教训、更新记忆，不打断当前工作；触发条件是「完成 N 个 agent step 后」或「上下文窗口被压缩时」。

4. **“Agent reviews before applying”：提案与复核分离**
   可选开关，让 agent 在第二个后台会话里复核并修订自己刚提出的记忆更新，然后再落盘。
   （它并不向你请求批准——是**自我二审**，不是人工审批。）

5. **`/doctor` 是记忆体检，不是聊天**
   当记忆层级漂移或膨胀时，`/doctor` 审计**放置位置、重复条目、系统提示的 token 占用**——三件最容易被忽视的腐化。

6. **整理前先备份**
   大整理（拆分大文件、合并重复、重构层级）会先备份当前仓库，再动手。

7. **并发写用 git worktree，不用全局锁**
   dreaming 与 memory doctor 这类记忆 subagent 各自在 worktree 里改记忆，因此可以并发更新而不阻塞主 agent。

8. **配额按“最新快照”计，不按历史**
   5 MiB / 50 MiB 上限，且只算每个分支或 tag 最新快照里的文件，不算 git 历史。
   于是“保留耐久知识、把大文件搬走只留摘要与检索指针”变成硬约束，而不是建议。

9. **技能有四级作用域，且 agent 级技能住在记忆里**
   `$MEMORY_DIR/skills`（agent 级，随 agent 身份走）· `.agents/skills`（项目级，属于仓库）· `~/.letta/skills`（本机）· bundled。
   文档点明多数 agent 的技能是 **device-bound**——换机器就没了；而把技能写进记忆，技能就跟着身份走。

10. **技能可以由“刚做完的一件事”直接生成**
    `skill-creator` 是内置技能，提示语就是：“能不能把我们刚做的数据库迁移变成一个项目级技能？”
    判据写得很清楚：某些动作序列**更适合被表示成技能而不是记忆**，因为它要被很多 agent 复用。

11. **它自己也承认供应链风险**：“Skills can contain malware and dangerous prompts that trick your agent into leaking your data.”

12. **Windows 上的诚实降级**：原生 Windows 默认关闭客户端自动 dreaming（需显式设环境变量开启），手动 `/dream` `/reflect` 仍可用。

### 改进建议

1. **P0 · memory_system**：记忆目录改为 git 版本化
   `.workbuddy/memory/` 初始化为独立 git 仓（或纳入主仓子模块语义），每次写入产出一条 commit，message 含触发原因与来源；
   明确“已保存（committed）”与“未提交改动”的边界；任何批量整理前自动 `git tag backup-<ts>`。
   价值：现在 MEMORY.md 是就地覆盖，改写历史不留痕，也回不到上一版。

2. **P0 · eval_observability**：新增记忆体检（memory doctor）
   对记忆目录输出三项报告——**错放**（属于项目决策的条目落在个人偏好里 / 反之）、**重复**（同义条目按相似度聚类）、**上下文占用**（哪些文件每轮进系统提示、各占多少 token）；
   产出可执行的重构提案（合并/迁移/降级为按需读取），纳入每周质量门。

3. **P1 · memory_system**：触发式整合 + 提案/复核分离
   触发条件写死为「每完成 N 个任务」或「上下文被压缩时」，而非“agent 想起来”；
   整合分两步：先产出提案（不落盘），再由独立会话复核后才 commit——**提出者与复核者不是同一个 pass**。
   这直接对上短板③（提出者=批准者=验收者）。

4. **P1 · skill_system**：任务完成后加一道“能否变技能”的显式判断
   在任务收尾清单里加一问：这次的动作序列是否会被复用？若是，用 `skill-creator` 落成技能，写明触发条件、步骤、验收；
   产物落 **agent 级作用域**（随项目无关、跟着 agent 走），与项目级技能分开。
   价值：487 条改进项至今 0 条变成技能，缺的就是这个转换动作。

5. **P1 · storage**：记忆并发写用 worktree/分支隔离
   后台整合、体检、批量重构各在自己的分支改，完成后再合并；不用全局锁，避免长任务阻塞日常写入。

6. **P2 · memory_system**：给记忆设“按最新快照计”的配额
   设上限（先 2 MiB），超限时先外迁大文件、只留摘要与指针；配额检查放在体检里。
   价值：这是唯一能让“只增不删”被迫收敛的机制。
