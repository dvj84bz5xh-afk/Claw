## 学习日期: 2026-11-10

### 学习项目: agentic-os-org/ANOLISA
- URL: https://github.com/agentic-os-org/ANOLISA
- Stars: 662（Rust, Apache-2.0, 更新 2026-11-10, 相关度 30 为今日最高）
- 一句话: 给 Agent 用的**系统软件栈**（不是框架）——把上下文、技能投递、工作区恢复、安全、可观测做成 OS 层能力，可装进现有系统，也可挂到现有 Agent 后面。

### 核心发现

1. **定位很克制：增强，不替换**
   "ANOLISA is a system software stack that enhances Agent applications, frameworks, and harnesses **without replacing them**." 现有 Agent 继续管自己的模型、界面、权限；ANOLISA 只在运行时环境里补四件事：上下文管理、技能发现、动作约束、执行记录。三种接入方式：预装镜像 / 装到已有 Linux / 用 adapter+plugin 挂到已有 Agent 后面。

2. **组件分层清楚，每层只回答一个问题**
   - 入口层：`cosh`（保留 Shell 手感的 AI 终端）+ **OS Skills**（给 Agent 看的系统手册：运维、监控、安全、DevOps 自动化）
   - 统一层：`AW`（把上面 Agent 框架和下面系统软件接起来，Provider 协议可扩展）
   - 语义层：`Tokenless`（工具输出压缩、**工具 schema 精简**、**命令改写**）/ `Agent Memory` / `SkillFS` / `Workspace Checkpoint (ws-ckpt)` / `Agent Security Core`（OS 级安全内核）/ `AgentSight`（轨迹、LLM 调用、Token 用量）

3. **SkillFS：技能以"稳定文件系统视图"投递**
   把散落在各处的技能组织成给 Agent 的稳定视图，Agent 按需发现、按需读——而不是调注册表 API 拿 JSON。**物理布局可以变，视图保持稳定**（仓库里同一条原则也写在别处：组件源码换目录时，命令、包名、release tag 都不变）。

4. **ws-ckpt：工作区快照 / 差异对比 / 回滚**
   Agent 改了文件之后，人可以看 diff、可以整批回滚。这与"会话状态 checkpoint"是两码事：一个是**对话能不能续跑**，一个是**磁盘上被改了什么、能不能退**。

5. **Tokenless 的三个省钱手段里，我们只做了一个**
   工具输出压缩（Claw 的 tool_registry 已有"输出压缩规则库 + 输出预算"）、**工具 schema 精简**（模型每次调用都要看的 schema 本身也是 token）、**命令改写**（把贵/慢的等价命令改写成便宜的）。后两个 Claw 完全没有。

6. **AgentSight：观测在 Agent 外面采**
   轨迹、LLM 调用、Token 用量由 AW/Provider 层截获，而不是等 Agent 自己上报。这和 10-29 nono 的"中介侧审计"同一条思路：**度量的位置不能在被度量对象内部**。

7. **安全边界说得明白**
   "The existing operating system, kernel, and sandbox provide the underlying resources and isolation mechanisms." —— 明确自己不造隔离，复用内核与沙箱；同时给出 OWASP Agentic Top 10 的对照，并诚实标注 **7 项 Full / 3 项 Partial**，还挂了 AARM 注册表条目。

8. **工程组织也值得抄**
   每个组件保留自己的构建与测试入口；Provider 有 contract tests；`specs/` 放贡献标准与组件 onboarding 规则；根目录与组件级各有一份 `AGENTS.md`（作用域不同，按需读）；`benchmark/` 放跨组件评测（ClawEval、SWE、Terminal Bench），组件自带 benchmark 留在组件内。

### 改进建议

1. **[P0][storage] 增加工作区快照（文件级 diff + 回滚）**
   现状：checkpoint 只管会话能否续跑；Agent 改了哪些文件、能不能退，没有独立载体（今天的日报/技能/配置都是直接写盘）。
   改法：任务开始时给工作区打内容哈希清单，结束或人工检查点时出 diff（新增/修改/删除），支持按文件或整批回滚到快照。
   价值：把"改了什么"从"看 git 猜"变成可审事实，接住短板③与⑥。

2. **[P0][skill_system] 本地技能文件变更检测 + 重扫**
   现状：10-29 那轮已抄来"远程技能来源证明"（签名/blocklist），但本地技能被改过没人知道。
   改法：给每个技能目录存内容哈希（ledger），发现/加载前比对，变更则标记"需重扫"并重跑安全检查；未通过不进可用集。
   价值：供应链信任的另一半——不只防"来路不明"，也防"来路明白但被改过"。

3. **[P1][tool_registry] 补上 schema 精简与命令改写**
   现状：只有输出压缩与输出预算，省的是"回来的 token"；"发出去的 token"没管。
   改法：①工具 schema 按当前任务裁剪（去掉无关参数说明、合并同类工具）；②对高频 shell 调用做等价改写（如 `cat` → 带行数限制的读、`ls -R` → `find -maxdepth`）。
   价值：一次性省两处固定开销，且不影响正确性（改写须登记原命令，便于审计）。

4. **[P1][skill_system] 技能稳定视图层**
   现状：技能散在 SkillsHub 与各工作区多根目录，靠注册表发现；路径一挪，引用就断。
   改法：对外只暴露一个稳定视图（逻辑路径 → 物理位置映射），加载/引用走逻辑路径；物理搬迁不改视图，只在映射表里换目标。
   价值：技能可搬迁、可挂载、可卸载，引用不再脆。

5. **[P1][eval_observability] 关键指标改在编排层采集**
   现状：token/耗时/工具调用多数由执行方自己记，等于自证。
   改法：在 orchestrator↔模型/工具的边界上统一截获调用与用量，Agent 侧只作为交叉校验来源。
   价值：与 nono 的"中介侧审计"合流，指标不再依赖被观测者的配合。

6. **[P2][claw_integration] 写清"增强不替换"的接入立场与能力边界**
   改法：文档里明确 Claw 与外部 Agent CLI（Claude Code/Codex）的关系是挂载增强（保留其模型、界面、权限），并诚实标注哪些边界 Claw 不提供（进程隔离、内核级约束）。
   价值：避免"装上了就等于隔离了"的误读——这是 10-29 之后的第二次同类教训。

### 判断
前面几轮学的都是"框架/运行时/记忆/协作"，这一轮第一次看**系统软件层**：它不解决"Agent 怎么想"，只解决"Agent 运行的环境该提供什么"。
对 Claw 最有价值的是两条被我们忽略的分界线：**会话状态 ≠ 工作区状态**（所以需要 ws-ckpt），**回来的 token ≠ 发出去的 token**（所以需要 schema 精简与命令改写）。
不引入依赖（Rust + Linux 内核态，跟 Windows + Python 环境不匹配），但组件划分可以直接当 Claw 的模块自检清单用：上下文/记忆/技能/工作区/安全/观测，六件我们都有，缺的是"工作区"这一件的文件级实现。
