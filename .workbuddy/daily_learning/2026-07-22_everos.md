### 核心发现

1. **Markdown-as-Truth三层存储栈** — `.md`文件为唯一真相源，SQLite（系统状态/审计）和LanceDB（向量+BM25）为可重建的派生索引。删除整个`.index/`目录，零记忆丢失，从Markdown树重建
2. **Cascade Daemon级联守护进程** — 实时监视`.md`文件变更，自动同步至SQLite/LanceDB索引，实现"编辑→索引→可检索"零延迟闭环
3. **Offline Memory Engine (OME) 离线反思引擎** — 会话间后台运行，合并episode聚类、提炼profile/skill、自进化记忆，无需LLM实时调用
4. **Orthogonal Retrieval正交五维检索** — 按`user_id × agent_id × app_id × project_id × session_id`五轴正交分区检索，不同空间绝不交叉
5. **User+Agent双轨记忆** — 用户侧(`episodes/profile`)和Agent侧(`cases/skills`)为独立一等公民表面，互不污染
6. **Knowledge Wiki知识百科** — 可编辑、源文件背书的Markdown知识页面，含分类体系、CRUD API和主题搜索
7. **零外部依赖本地栈** — Markdown+SQLite+LanceDB三件套，无需MongoDB/Elasticsearch/Redis

### 存储路径架构

```
~/.everos/                         ← memory root
├── default_app/                   ← <app_id>
│   └── default_project/           ← <project_id>
│       ├── users/<user_id>/
│       │   ├── user.md            ← 单文件profile
│       │   ├── episodes/          ← 每日追加日志
│       │   └── .atomic_facts/     ← 隐藏原子事实
│       ├── agents/<agent_id>/
│       │   ├── skills/            ← Agent技能
│       │   └── cases/             ← Agent案例
│       ├── wiki/                  ← Knowledge Wiki
│       └── .index/                ← SQLite+LanceDB（可重建）
```

### 改进建议

1. **P0: 实施Markdown-as-Truth存储架构** — Claw的`.workbuddy/memory/`文件应升级为规范化的Markdown真相源，所有检索索引（FTS5+向量）为可重建的派生层。删除`.index/`不丢失任何记忆
2. **P0: 引入Cascade Daemon级联守护** — 在memory_system中实现文件监视器，编辑MEMORY.md或日志文件后自动触发SQLite+向量索引重建，实现"编辑→索引→可检索"零延迟
3. **P0: 实现OME离线反思引擎** — 在进化引擎中增加后台反思步骤：合并相邻episode、提炼用户profile偏好、压缩冗余Agent skill描述、自进化记忆质量
4. **P0: 正交五维分区检索** — 在rag_engine中实现`user_id×agent_id×app_id×project_id×session_id`五轴分区，不同空间绝不交叉搜索
5. **P1: User+Agent双轨记忆表面** — 分离用户侧(profile/episode/atomic_fact)和Agent侧(skill/case/trajectory)为独立一等公民，互不污染
6. **P1: Knowledge Wiki知识百科系统** — 在rag_engine中增加wiki子模块：Markdown知识页+分类体系+CRUD API+主题搜索，背书源文件
7. **P1: 本地栈替代外部DB** — 用SQLite+LanceDB(Lance)替代任何对外部DB的依赖，实现真正的local-first部署
