## 学习日期: 2026-10-29

### 学习项目: nolabs-ai/nono
- URL: https://github.com/nolabs-ai/nono
- Stars: 4,733 (Rust, Apache-2.0, 更新 2026-10-28)
- 背景: Sigstore 团队出品（PyPI/npm/brew/Maven Central 用的签名标准就是他们做的），OpenSSF Best Practices 认证
- 定位: **Agent 运行时安全层** —— 不是框架、不是记忆、不是技能市场，而是把"Agent 能碰什么"从 prompt 约定变成内核强制

### 核心发现

**1. 监督进程 = 能力代理（Capability Broker），不是权限判断函数**
每次工具调用依据"该次调用选定的 command sandbox policy"启动**全新沙箱**，且**不继承会话沙箱的授权**：文件、网络、环境变量、凭据全部从最小运行时基线开始，逐项显式授予。
→ 与"会话里挂一个 permission 钩子做 if-else 判断"是两种范式：后者靠上下文传递（漏一个分支就渗漏），前者靠**默认拒绝 + 每次重新派生**。

**2. 工具间调用是双向边授权，缺边不回退**
- 会话能直接跑什么 → `commands.<name>.from.session`
- 一个中介命令能继续调什么 → 调用方 `can_use` + 被调方 `from.<caller>`，**两条边同时满足才放行**
- 缺调用者边**不回退**到直接命令沙箱（这是最容易写错的地方）
- 链式调用中每一跳的代理策略**各自独立，从不合并**

示例：`git` 可以调 `ssh`，但 agent 不能直接调 `ssh` —— 同一条网络能力，按**调用路径**而不是按**工具名**授权。

**3. 凭据永不进入 Agent 的进程与上下文**
四类凭据：`local-socket`（如 SSH agent）/ `raw-file` / `proxy`（带 endpoint 策略，支持 AWS SigV4，真实密钥不进沙箱）/ `ambient`（捕获后只暴露 **phantom token**，可用 `format` 模板塑形如 `sk-ant-oat01-{}`）。
`proxy` 与 `allow_all` 互斥；需要代理但无可用代理时**启动即 fail closed**，不静默降级为直连。
另：`PATH`、`NONO_*`、`OP_*_TOKEN` 永不转发；`LD_*`/`DYLD_*` 仅在精确命名时转发（裸通配 `*` 会跳过它们）。

**4. 技能/钩子/指令文件的来源证明（Sigstore）**
- `trust-policy.json` 与沙箱策略**分离**，位于项目根；`includes` 用 glob 圈定"必须被签名"的文件：`SKILLS*`、`CLAUDE*`、`.claude/**/*.md`、`*.py`
- **匹配即必须签名**，签名产物是 Sigstore Bundle v0.3 sidecar，或 `--multi-subject` 合成单一 `.nono-trust.bundle`
- `blocklist.digests` 在**所有验证之前**检查，命中即硬拒绝 —— **即使 `warn`/`audit` 模式也硬拒绝**
- `enforcement`: `deny`(默认，失败则 Agent 无法启动) / `warn` / `audit`
- 签名只证明**来源 + 完整性**，README 明确写"不证明内容安全或正确" —— 与昨天 agent-skills-platform 的 evals 分工清晰

**5. 用户级策略是信任锚，项目级不能削弱**
三层合并：Embedded（编译进二进制）→ User（`~/.config/nono/trust-policy.json`，"我信任谁"）→ Project（"验什么"）。
publishers / blocklist / includes 取**并集**，enforcement 取**最严格**（deny > warn > audit）。**恶意项目无法降低你的信任阈值** —— 没有用户级策略时 nono 会警告"项目级策略不具权威性"。

**6. 验证时机分两档，且平台差异诚实声明**
- 启动扫描：不遵守 `.gitignore`（防止用 ignore 绕过验证），跳过 `.git`/`node_modules`/`target`/`dist`
- 运行时：Linux（seccomp-notify）拦截每次 `openat()`，会话中途下载的新文件**首次打开即验**；macOS（Seatbelt）**只能启动时验**，改为对通过文件 `deny file-write-data` 使其会话内不可变，并**明确写出"会话中途新出现的、父目录可读的文件会被读取"**

**7. 可写可执行信任门 + 原子回滚 + 可验证审计**
- 若某可执行文件**或其父目录**在能力集下可写 → 中介直接拒绝（防 TOCTOU 替换），降级需显式 `allow_writable_executable`
- 审计事件由 **broker 记录而非工具自报**，decision 来自封闭词表，session 摘要覆盖 → `nono audit verify` 能检出篡改
- 原子回滚：审查文件变更，从**验证过的快照**恢复被误改的受追踪文件
- `stdio` 中介带字节上限：`truncate` 转发到上限后继续排空 / `terminate` / `deny`，防大输出外泄或撑爆 broker

### 改进建议
1. **P0 · tool_registry — 调用级能力派生**
   现在 Guardrails 是"会话级四钩三判"，工具一旦被批准，后续调用沿用同一授权。改为：每次工具调用由 broker 按该次调用的 policy 派生独立能力集（fs 读/写目录、域名白名单、env 白名单、凭据句柄），**不继承会话授权**；工具间调用需双向前提（调用方 `can_use` + 被调方 `from.<caller>`），缺边即拒且不回退。价值：把"权限渗漏"从审查问题变成结构不存在。

2. **P0 · skill_system — 技能来源证明**
   10-27 刚加了"HTTP 拉取技能包"，但拉下来只验 tar 结构、不验来源 —— 这是供应链缺口。补齐：`skill-trust.json` 用 `includes` glob 圈定 `SKILL*` / `AGENTS*` / 钩子脚本，匹配即必须带 Sigstore bundle；未签名默认**拒载**（不是警告）；`blocklist` 摘要优先检查且不可被 warn/audit 降级；用户级 trust anchor 定义"信任谁"，项目级只能"验什么"，不可削弱。

3. **P1 · claw_integration — 可写可执行信任门 + fail closed**
   执行前检查：目标可执行文件或其父目录在本次能力集下可写 → 拒绝执行（防运行期间被替换）；依赖的能力（代理/凭据/审计后端）不可用时**启动失败**，不静默降级为直连或跳过审计。

4. **P1 · eval_observability — 审计由中介记录，工具不得自证**
   审计事件由执行中介写入（工具只能"请求"，不能"记录结果"）；decision 用封闭词表；会话汇总加摘要，`audit verify` 一条命令验证未篡改。价值：昨天提到的"提出者=批准者=验收者"问题，在审计层同样存在 —— 现在是自己写自己的日志。

5. **P2 · storage — 原子回滚**
   对声明为可写的路径在运行前做内容寻址快照（`.claw/snapshots/<run>/`），运行后给出变更清单；误改可单文件恢复且快照本身可校验。比 git 更细（无 commit 语义包袱），比备份更轻。

### 判断
Claw 当前的权限模型是"信任 Agent 的行为，再用钩子兜住"，nono 的模型是"**不信任，只授予**"。这个差别不是强度问题，是**归属**问题：钩子写在 Agent 的进程里，策略也在同一个进程里读，理论上被绕过的路径总存在；nono 把策略、凭据、审计全部搬到 Agent 之外的 broker，Agent 只能拿到 phantom。

对 Claw 最现实的落地不是照抄内核沙箱（Windows 上 Landlock/Seatbelt 都没有对应物），而是抄它的**三个抽象**：①每次调用派生能力集 ②工具间双向边授权 ③策略/凭据/审计三样都不在 Agent 进程内。这三条是纯设计，不依赖内核。
