## 06:52 推进 P0 #23 — LifespanManager 资源生命周期管理

### 落地项目：P0 #23 (mcp-lifespan)
**来源**: modelcontextprotocol/python-sdk  
**改进**: Lifespan API 资源生命周期管理（@asynccontextmanager）

### 实施内容

#### 1. 新增 `agent-core/lifespan_manager.py` (~700行)
**核心组件**:
- **@lifespan 装饰器**: 将生成器函数转为上下文管理器（支持同步/异步）
- **LifespanManager 资源管理器**: 集中注册、初始化、清理资源
- **预置资源工厂**:
  - `sqlite_lifespan()`: SQLite 连接生命周期
  - `jsonl_lifespan()`: JSONL 文件写入生命周期（跨平台文件锁）
  - `api_session_lifespan()`: API 会话生命周期（HTTP 连接池）
  - `subprocess_lifespan()`: 子进程生命周期

**设计亮点**:
- 异常安全：即使初始化失败，也保证已分配资源的清理
- 跨平台兼容：Windows（msvcrt）和 Linux/Mac（fcntl）文件锁
- 自动清理：持有所有上下文管理器引用，防止 GC 提前回收

#### 2. 修复过程（Bug 修复）
1. **Bug #1**: `__enter__()` 返回 `LifespanContext` 而非 `self` → 演示代码无法调用 `register_*()`  
   **修复**: 修改 `__enter__()` 返回 `self`，通过 `get_ctx()` 获取上下文

2. **Bug #2**: `_LifespanContextManager` 实例是局部变量，函数返回后被 GC 回收 → 资源被立即清理  
   **修复**: 在 `LifespanManager` 中添加 `self._cms: list = []` 持有所有引用

3. **Bug #3**: `fcntl` 模块在 Windows 上不可用 → `jsonl_lifespan()` 初始化失败  
   **修复**: 使用 `platform.system()` 检测 OS，Windows 上跳过文件锁（演示环境）

4. **Bug #4**: 资源管理逻辑有误 → `register()` 展开字典键值对导致资源 ID 错误  
   **修复**: 重构设计，`@lifespan` 装饰的生成器 `yield` 的值被整体保存为一个资源
