## 智能进化学习 第102轮 — NVIDIA/OpenShell (⭐21,650, 相关度27)

**选题**：57 个候选中比掉 `stablyai/orca`(⭐125K, 多 agent 各 worktree 并行)、`herdrdev/herdr`(⭐51K, 终端会话不中断)——这两者补的"并行编排/会话持久化"与 Claw 已有 checkpoint 续跑、并行 executor、Durable Execution 重叠；OpenShell 补的是**执行点位置**，近 8 轮完全没碰。

**核心发现**
1. 内核级强制：agent 独立 sandbox，内核管文件访问与系统调用，网络连接出沙箱前必过策略检查 → 强制点在 harness 进程之外。
2. 策略变更由 prover 先算"这条变更会新允许什么"（带凭证访问新主机 / 调新 API method），命中风险就挂起等人工 → **批准对象是可枚举的能力集合，不是文本 diff**。
3. advisor(提议) 与 prover(判定) 分离 → "进化≠自己改自己"的机制化写法。
4. 凭证-端点绑定：agent 永不见明文，只在发往已批准 endpoint 时注入。
5. 三层控制面 gateway / supervisor / sandbox；策略与审计不在 agent 可写区。
6. 强制依赖诚实声明（"Your CNI must enforce NetworkPolicy"）。

**结论**：语义层前 8 轮补得差不多了，但所有强制都在被治理对象自己的进程里。治理强度取决于强制点位置，不取决于策略描述得多细。→ MEMORY.md 增第十四条短板。
