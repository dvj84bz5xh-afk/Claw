## 核心架构

```
Channel → MessageBus → AgentLoop → AgentRunner → Provider/Tools
                    ↓               ↓
              Hook系统          Stream处理
              子Agent委派       工具调用
```

**AgentLoop**（面向Channel的Turn编排）:
- 接收消息 → 会话/工作区选择 → 上下文构建 → Hook链 → 输出

**AgentRunner**（面向模型的循环）:
- Provider调用 → 流式Delta处理 → 工具调用执行 → 工具结果回传

## 关键创新点

### 1. Dream两阶段记忆整合 [P0]
- **Consolidator**: 会话结束后压缩到history.jsonl（append-only, cursor-based）
- **Dream**: 定期整合history → MEMORY.md/SOUL.md/USER.md
- GitStore: 长期记忆文件的版本历史

### 2. AgentLoop/AgentRunner分离 [P0]
- Loop负责"何时调用"（turn编排、hook、channel路由）
- Runner负责"如何调用"（provider、stream、tool execution）
- 职责清晰，便于扩展不同Provider和不同Channel

### 3. Heartbeat主动任务系统 [P0]
- 读取HEARTBEAT.md中的Active Tasks
- 定时触发执行，抑制无用结果
- 从被动响应进化到主动执行

### 4. Model Presets命名配置 [P1]
- 命名模型配置（如"fast"/"smart"/"vision"）
- 支持fallback链，per-session切换
- 简化用户配置，提升可维护性

### 5. AgentHook三层生命周期 [P1]
- AgentHookContext（per-iteration）
- AgentRunHookContext（run级）
- AgentTurnHookContext（turn级）
- before_run/after_run/before_iteration/on_stream等

### 6. Auto Compact空闲压缩 [P1]
- 空闲时主动压缩旧会话上下文
- 缓解长期运行Agent的上下文膨胀

### 7. 子Agent并发控制
- maxConcurrentSubagents限制并发数
- failOnToolError控制错误传播策略
