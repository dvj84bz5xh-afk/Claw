### 核心发现

1. **"Skill is Memory, Memory is Skill"** — 把 Agent 记忆直接构建成 **skill Markdown 文件格式**，记忆即技能文件，人类可读/可编辑/可分享，杜绝"不透明记忆污染上下文"
2. **Store 学习管道**（`Session messages → Task complete/failed 触发 → Distillation 蒸馏 → Skill Agent 路由 → Update Skills`）：任务完成/失败作为学习触发器，LLM 蒸馏"什么 work 了/失败了/用户偏好"，Skill Agent 决定写入已有 skill 还是新建
3. **Recall 渐进式披露**：给 Agent `get_skill` / `get_skill_file` 工具，Agent 主动按需拉取 —— **无 embedding 检索，agent in the loop**，用工具调用+推理替代语义 top-k
4. **Plain file, any framework**：记忆以 Markdown 文件存储，**无 embeddings、无 API 锁定**，可 Git/grep、可 mount 到 sandbox，跨 LangGraph/Claude/AI SDK/任意框架复用
5. **用户设计结构**：通过 `SKILL.md` 定义记忆的 schema、命名与文件布局（如一联系人一文件、一项目一文件），系统负责 extraction/routing/writing
6. **配套能力**：Context Engineering（summary 压缩 + editing strategies）、Disk（虚拟持久文件系统）、Sandbox（隔离 bash/python 执行 + **mountable skills**）、Agent Tools（disk/sandbox/skill 工具供 function calling）
7. **架构**：Client(pip/npm) → API(FastAPI+MQ) → Core → Infrastructure(PostgreSQL/S3/Redis/RabbitMQ) + Web Dashboard

### 改进建议

1. **P0｜memory_system**: 引入 Skill-as-Memory 统一记忆层 —— 记忆以 skill Markdown 文件存储（Memory is Skill, Skill is Memory），用 SKILL.md 定义 schema/命名/文件布局，系统自动 extraction/routing/writing，统一 Claw 当前分离的 memory_system 与 skill_system
2. **P0｜skill_system**: 任务结果触发蒸馏学习 —— 任务完成/失败作为学习触发器，LLM 蒸馏 what worked/failed + 用户偏好，Skill Agent 决定路由到已有或新建 skill，强化 Claw 自动学习管道
3. **P1｜tool_registry**: Skill Content Tools 工具化召回（get_skill/get_skill_file）—— 渐进式披露 + agent in the loop，用工具调用+推理替代语义 embedding top-k 召回
4. **P1｜storage**: Skill 文件挂载进 sandbox（mountable skills）—— skill Markdown 可直接 mount 到隔离 sandbox，Agent 用 bash/python 直接读写操作
5. **P2｜context_injector**: Context Engineering 摘要压缩 + 编辑策略（summaries + editing strategies），强化 Auto Compact

### 价值评估
Acontext 与 Claw 的 **memory_system + skill_system** 双模块高度互补：它用极简的"文件即记忆、记忆即技能"范式，解决了 Claw 当前 memory 与 skill 分离、记忆不透明不可审计的问题。其"任务结果触发蒸馏 + Skill Agent 路由"直接可作为 Claw 自进化管道的落地参照。
